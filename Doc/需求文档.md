## 1. 背景与愿景

### 1.1 系统定位

NewLife.Modbus 是基于 [NewLife.IoT](https://github.com/NewLifeX/NewLife.IoT) 标准接口体系的 .NET Modbus 协议库，为工业物联网应用开发者提供协议完整、接口统一、性能优越、开箱即用的 Modbus 协议栈，覆盖从嵌入式网关到云端服务的各类应用场景。

Modbus 自 1979 年由 Modicon 公司发布以来，已成为 PLC、变频器、仪表、传感器等工业设备互联的事实标准。该协议公开发布、免版税，被广泛部署于 SCADA、DCS、BAS 等工业控制系统中。

### 1.2 愿景

为 .NET 工业物联网生态提供一套**协议最完整、功能码覆盖最全、传输变体最丰富**的 Modbus 协议库，支持 IoTEdge 网关及各类工业应用开发，让 .NET 开发者能用最少的代码完成工业设备对接，同时具备充分的可扩展性和可观测性。

## 2. 核心目标

| 编号 | 目标 | 所属层级 | 一句话描述 |
|:----:|------|:--------:|-----------|
| CORE | 协议核心层 | 基础层 | 实现 Modbus 应用协议规范 V1.1b3 定义的 PDU/ADU 编解码、CRC/LRC 校验、地址模型、异常体系，提供零分配编解码能力 |
| TRAN | 传输变体 | 基础层 | 支持 7 种传输变体（TCP(含TLS)/UDP/RTU/ASCII/RtuOverTCP/RtuOverUDP/RtuSimple），覆盖网络和串口两大类通信媒介，TCP 支持 TLS 安全传输（通过 SslProtocol 属性内建集成） |
| FC | 功能码 | 核心层 | 实现全部 19 个功能码（12 公共 + 7 进阶），覆盖工业现场 99% 以上的常用操作 |
| SLAVE | 从机实现 | 核心层 | 提供 TCP/RTU/ASCII 三种从机实现，支持多客户端并发、多从站路由、广播模式和自定义数据回调 |
| DRV | 驱动集成 | 集成层 | 实现 NewLife.IoT 标准 IDriver 接口，6 种驱动可选，支持批处理合并和单连接复用，可零代码接入 IoTEdge 平台 |
| ENH | 增强特性 | 增强层 | 断线自动重连、异步 API、多从站网络模型、自定义功能码注册，填补与 NModbus 的功能差距 |

> 编码说明：采用字母前缀方案，各模块按前置依赖排序（基础→核心→集成→增强→测试）。每个模块下的详细功能点列表见 [功能清单.md](功能清单.md)。

## 3. 功能需求

### 3.1 CORE — 协议核心层

| 编码 | 功能 | 一句话描述 |
|:----:|------|-----------|
| CORE-1 | Modbus 抽象基类 | 提供模板方法模式的抽象基类，定义 Read/Write 路由和 SendCommand 抽象，所有传输变体统一继承 |
| CORE-2 | 通用消息编解码 | PDU = 功能码(1B) + 数据(NB) 结构的通用编解码 |
| CORE-3 | RTU 消息编解码 | 地址(1B) + PDU + CRC-16(2B) 的 RTU 帧编解码 |
| CORE-4 | ASCII 消息编解码 | 冒号帧头 + ASCII 十六进制 + LRC(2C) + CR/LF 的 ASCII 帧编解码 |
| CORE-5 | MBAP 消息编解码 | 事务ID(2) + 协议标识(2) + 长度(2) + 单元标识(1) 的 TCP/UDP MBAP 头编解码 |
| CORE-6 | CRC-16-MODBUS 校验 | 查表法实现多项式 0xA001 的 CRC 校验 |
| CORE-7 | LRC 校验 | 字节和取二补数的 LRC 校验算法 |
| CORE-8 | 功能码枚举 | 定义全部 19 个功能码的枚举，附带 Description 特性 |
| CORE-9 | 错误码枚举 | 定义 11 个标准 Modbus 异常码（01~0B） |
| CORE-10 | Modbus 异常类 | 包含功能码和错误码信息的专用异常 |
| CORE-11 | 地址区域定义 | 四区地址模型枚举：DO/DI/AI/AO |
| CORE-12 | 地址解析 | 支持 DO/0x/DI/1x/AI/3x/AO/4x 多格式 + 位域语法 |
| CORE-13 | 寄存器单元模型 | 16 位保持寄存器的地址+值数据模型 |
| CORE-14 | 线圈单元模型 | 1 位线圈的地址+布尔数据模型 |
| CORE-15 | 设备标识模型 | FC43 读设备标识的响应数据模型 |
| CORE-16 | Modbus 协议工厂 | 根据配置字符串动态创建不同传输变体的 Modbus 实例 |

### 3.2 TRAN — 传输变体

| 编码 | 功能 | 一句话描述 |
|:----:|------|-----------|
| TRAN-1 | ModbusTCP（含 TLS） | 标准 Modbus TCP/IP 实现，MBAP 头 + PDU，端口 502；设置 SslProtocol 后自动启用 TLS 安全传输，支持客户端证书验证 |
| TRAN-2 | ModbusUDP | Modbus over UDP 无连接传输实现 |
| TRAN-3 | ModbusRtuOverTCP | RTU 帧（含 CRC）通过 TCP 传输 |
| TRAN-4 | ModbusRtuOverUDP | RTU 帧（含 CRC）通过 UDP 传输 |
| TRAN-5 | ModbusIp 网络基类 | TCP/UDP 子类的公共抽象，统一管理 Server 地址和客户端生命周期 |
| TRAN-6 | ModbusRTU 串口 | 串口二进制紧凑格式 + CRC-16 校验 |
| TRAN-7 | ModbusASCII 串口 | 串口 ASCII 十六进制格式 + LRC 校验 |
| TRAN-8 | ModbusRtuSimple 轻量串口 | 直接操作 SerialPort 的轻量实现，减少依赖，适用于资源受限边缘设备 |
| TRAN-9 | 串口控制器抽象 | ISerialPort 接口隔离具体串口实现，便于单元测试注入 Mock |

| FC-02 | FC02 | 读离散输入 | 读取从机离散输入状态，最多 2000 个输入 |
| FC-03 | FC03 | 读保持寄存器 | 读取从机保持寄存器值，最多 125 个寄存器 |
| FC-04 | FC04 | 读输入寄存器 | 读取从机输入寄存器值，最多 125 个寄存器 |
| FC-05 | FC05 | 写单个线圈 | 写入单个线圈，值 0xFF00（ON）或 0x0000（OFF） |
| FC-06 | FC06 | 写单个寄存器 | 写入单个保持寄存器 |
| FC-07 | FC08 | 诊断 | 子功能码诊断，支持 Echo Test |
| FC-08 | FC15 | 写多个线圈 | 批量写入多个线圈，最多 1968 个线圈 |
| FC-09 | FC16 | 写多个寄存器 | 批量写入多个保持寄存器，最多 123 个寄存器 |
| FC-10 | FC21 | 写文件记录 | 写入文件记录（WriteFileRecord） |
| FC-11 | FC23 | 读写多寄存器 | 单请求内先写后读多个保持寄存器 |
| FC-12 | FC43 | 读设备标识 | 读取从机设备标识码，返回 ModbusDeviceInfo 模型 |

### 3.4 SLAVE — 从机实现

| 编码 | 功能 | 一句话描述 |
|:----:|------|-----------|
| SLAVE-1 | TCP 从机服务 | 基于 NetServer 的高性能 TCP 从机，监听端口 502，支持多客户端并发连接 |
| SLAVE-2 | 会话处理 | OnReceive 中解析 19 个功能码请求并路由响应，优先匹配自定义处理器 |
| SLAVE-3 | 寄存器数据存储 | List`<RegisterUnit>` 保持寄存器 / 输入寄存器数据存储 |
| SLAVE-4 | 线圈数据存储 | List`<CoilUnit>` 线圈 / 离散输入数据存储 |
| SLAVE-5 | RTU 串口从机 | ModbusRtuSlave 串口 RTU 从机实现 |
| SLAVE-6 | ASCII 串口从机 | ModbusAsciiSlave 串口 ASCII 从机实现 |

### 3.5 DRV — 驱动集成

| 编码 | 功能 | 一句话描述 |
|:----:|------|-----------|
| DRV-1 | ModbusDriver 基类 | 继承 DriverBase 实现 IDriver 接口，单连接复用 + 批处理合并 |
| DRV-2 | ModbusTcpDriver | TCP 协议的 IoT 驱动实现 |
| DRV-3 | ModbusUdpDriver | UDP 协议的 IoT 驱动实现 |
| DRV-4 | ModbusRtuOverTcpDriver | RTU over TCP 协议的 IoT 驱动实现 |
| DRV-5 | ModbusRtuOverUdpDriver | RTU over UDP 协议的 IoT 驱动实现 |
| DRV-6 | ModbusRtuDriver | 串口 RTU 协议的 IoT 驱动实现 |
| DRV-7 | ModbusAsciiDriver | 串口 ASCII 协议的 IoT 驱动实现 |
| DRV-8 | ModbusParameter 参数模型 | 驱动参数基类，支持 Host/ReadCode/WriteCode/Timeout/BatchStep/BatchSize/BatchDelay 配置 |
| DRV-9 | IP 参数模型 | ModbusIpParameter/ModbusTcpParameter/ModbusUdpParameter 网络参数 |
| DRV-10 | 串口参数模型 | ModbusRtuParameter 串口参数，支持 PortName/Baudrate/DataBits/Parity/StopBits |
| DRV-11 | BuildSegments 批处理 | 地址分段合并算法，将连续地址的点位合并为单次 Modbus 请求 |

### 3.6 ENH — 增强特性

| 编码 | 功能 | 一句话描述 |
|:----:|------|-----------|
| ENH-1 | 断线自动重连 | MaxRetry/RetryInterval 配置自动重连，TCP/UDP/RTU/ASCII 通用 |
| ENH-2 | 异步 API | 所有公共 API 均提供 async/await 异步版本，同时保留同步桥接 |
| ENH-3 | 广播模式 | Slave 端识别地址 0 广播，执行写操作但不发送响应 |
| ENH-4 | 多从站网络模型 | SlaveInstances 字典按站号路由到独立从站实例（含独立 Registers/Coils/DeviceInfo） |
| ENH-5 | 数据变更事件 | BeforeRead（读取前刷新数据）和 AfterWrite（写入后同步硬件）事件回调 |
| ENH-6 | 自定义功能码注册 | Master 端 RegisterFunctionCode 和 Slave 端 RegisterFunctionHandler，支持用户自定义区段 |
| ENH-7 | Enron Modbus（32 位浮点扩展） | 兼容 Enron/Daniel Modbus 32 位 IEEE 754 浮点寄存器，继承 ModbusTcp，提供 ReadFloat/WriteFloat/WriteFloats 完整 API，工厂已注册 `enron://` Scheme，TCP/UDP 传输 |
