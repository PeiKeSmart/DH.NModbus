# NewLife.Modbus 架构设计

> 版本: v2.2 | 更新: 2026-07-22
> 关联: [需求文档](需求文档.md) | [功能清单](功能清单.md) | [竞品分析](竞品分析.md)

## 1. 架构概览

NewLife.Modbus 采用四层分层架构，各层职责清晰、依赖单向向下：

```
┌────────────────────────────────────────────────────────────────┐
│                      应用层（Application）                      │
│   WinModbus 演示程序 / IoTEdge 网关 / 用户应用代码            │
└───────────────────────────┬────────────────────────────────────┘
                            │ IDriver / 直接调用
┌───────────────────────────▼────────────────────────────────────┐
│                  驱动层（Driver Layer）                         │
│  ModbusDriver（抽象）                                          │
│  ├─ ModbusTcpDriver        ├─ ModbusUdpDriver                  │
│  ├─ ModbusRtuDriver        ├─ ModbusAsciiDriver                │
│  ├─ ModbusRtuOverTcpDriver └─ ModbusRtuOverUdpDriver           │
│                                                                 │
│  职责：IDriver 接口实现，连接生命周期管理，批处理合并（BuildSegments） │
└───────────────────────────┬────────────────────────────────────┘
                            │ Modbus 实例
┌───────────────────────────▼────────────────────────────────────┐
│                  协议层（Protocol Layer）                       │
│  Modbus（抽象基类）                                             │
│  ├─ ModbusIp（网络基类）                                       │
│  │   ├─ ModbusTcp          ├─ ModbusUdp                        │
│   │   ├─ ModbusTcp(含TLS)   ├─ ModbusRtuOverTcp                 │
│  │   └─ ModbusRtuOverUdp                                       │
│  ├─ ModbusEnron（32位浮点扩展）                                  │
│  ├─ ModbusRtu（串口RTU）                                        │
│  ├─ ModbusAscii（串口ASCII）                                     │
│  └─ ModbusRtuSimple（轻量级串口）                               │
│                                                                 │
│  消息编解码：                                                   │
│  ModbusMessage → ModbusRtuMessage / ModbusAsciiMessage / ModbusIpMessage │
│                                                                 │
│  地址与功能：ModbusRange / ModbusAddress / FunctionCodes / ErrorCodes    │
│  工厂：ModbusFactory（根据配置创建 Modbus 实例）               │
│  从机：ModbusSlave（NetServer）/ ModbusSession（NetSession）   │
└───────────────────────────┬────────────────────────────────────┘
                            │ 字节流
┌───────────────────────────▼────────────────────────────────────┐
│                  传输层（Transport Layer）                      │
│   TCP Socket（NewLife.Net）/ UDP Socket / SerialPort           │
│   LengthFieldCodec（TCP 粘包处理）/ CRC / LRC 校验             │
└────────────────────────────────────────────────────────────────┘
```

## 3. 数据模型设计

### 3.1 Modbus PDU / ADU 结构

Modbus 协议规范定义了三层数据单元：

```
RTU ADU：  [地址(1B)] [功能码(1B)] [数据(0-252B)] [CRC(2B)]
ASCII ADU：[:] [地址(2C)] [功能码(2C)] [数据(0-504C)] [LRC(2C)] [CR][LF]
TCP ADU：  [MBAP头(7B)] [功能码(1B)] [数据(0-252B)]
           MBAP = 事务ID(2) + 协议标识(2) + 长度(2) + 单元标识(1)
```

### 3.2 消息类层次

```
ModbusMessage（通用基类）
├─ Host     : Byte    // 从机地址（1-247）
├─ Code     : FunctionCodes  // 功能码
├─ Payload  : IPacket        // 有效数据
│
├─ ModbusRtuMessage    // RTU 变体：追加 CRC-16 校验
├─ ModbusAsciiMessage  // ASCII 变体：冒号帧头 + LRC 校验 + CR/LF 帧尾
└─ ModbusIpMessage     // TCP/UDP 变体：MBAP 头（7字节）
    ├─ TransactionId : UInt16  // 事务标识符
    ├─ ProtocolId    : UInt16  // 协议标识（固定 0x0000）
    └─ Length        : UInt16  // 后续字节数（含单元标识）
```

### 3.3 地址模型

Modbus 标准四区地址模型：

| 区域 | 枚举值 | 地址前缀 | 数据类型 | 默认读码 | 默认写码 |
|------|--------|---------|---------|---------|---------|
| DO（线圈输出） | `ModbusRange.DO` | `0x` / `DO` | 1 bit，可读写 | FC01 | FC05 |
| DI（离散输入） | `ModbusRange.DI` | `1x` / `DI` | 1 bit，只读 | FC02 | — |
| AI（输入寄存器） | `ModbusRange.AI` | `3x` / `AI` | 16 bit，只读 | FC04 | — |
| AO（保持寄存器） | `ModbusRange.AO` | `4x` / `AO` | 16 bit，可读写 | FC03 | FC06 |

地址解析流程（`ModbusAddress.TryParse`）：

```
输入字符串
  ↓ 去掉位域（":"或"."后的部分）
  ↓ 前缀识别：DO/0x → Range=DO; DI/1x → Range=DI; AI/3x → Range=AI; AO/4x → Range=AO
  ↓ 无前缀：按数值范围自动推断（0-9999=DO, 10000-19999=DI, 30000-39999=AI, 40000-49999=AO）
  ↓ 提取数字地址（ToInt()）
  → ModbusAddress { Range, Address }
```

### 3.4 驱动参数模型

```
ModbusParameter（基类）
├─ Host       : Byte     // 从机站号，默认 1
├─ ReadCode   : FunctionCodes  // 默认读功能码（0=按区域自动选择）
├─ WriteCode  : FunctionCodes  // 默认写功能码（0=按区域自动选择）
├─ Timeout    : Int32    // 通信超时，默认 3000ms
├─ BatchStep  : Int32    // 批处理地址间隔阈值，默认 1
├─ BatchSize  : Int32    // 单批点位最大数量
└─ BatchDelay : Int32    // 两次批请求间隔，默认 0ms

ModbusIpParameter : ModbusParameter
└─ Server     : String   // "host:port" 格式，默认 "127.0.0.1:502"

ModbusTcpParameter : ModbusIpParameter
└─ ProtocolId : UInt16   // MBAP 协议标识，默认 0x0000

ModbusRtuParameter（RTU 串口）
├─ PortName   : String   // 串口名，如 "COM3" / "/dev/ttyS0"
├─ Baudrate   : Int32    // 波特率，默认 9600
├─ DataBits   : Int32    // 数据位，默认 8
├─ Parity     : Parity   // 校验位，默认 Even
└─ StopBits   : StopBits // 停止位，默认 1
```

## 4. 协议层详细设计

### 4.1 Modbus 抽象基类（`Modbus`）

核心抽象设计：所有传输变体继承 `Modbus`，实现 `SendCommand(ModbusMessage)` 抽象方法。

```csharp
public abstract class Modbus : DisposeBase, IModbus
{
    // 配置属性
    public Int32 Timeout { get; set; } = 3000;
    public Int32 BufferSize { get; set; } = 256;
    public Boolean ValidResponse { get; set; } = true;
    public ITracer? Tracer { get; set; }

    // 模板方法：按功能码路由到具体处理
    public virtual IPacket? Read(FunctionCodes code, Byte host, UInt16 address, UInt16 count);

    // 高级 API（Master 侧）
    public virtual Byte[]? ReadCoil(Byte host, UInt16 address, UInt16 count);
    public virtual UInt16[]? ReadRegister(Byte host, UInt16 address, UInt16 count);
    public virtual Boolean WriteCoil(Byte host, UInt16 address, Boolean value);
    public virtual Boolean WriteRegisters(Byte host, UInt16 address, UInt16[] values);
    // ... 其余 FC 对应方法

    // 核心抽象：子类必须实现具体传输
    protected abstract ModbusMessage? SendCommand(ModbusMessage message);
}
```

**设计决策**：使用模板方法模式，`Read()` 负责按功能码路由和追踪埋点，`SendCommand()` 由子类实现具体传输（TCP/UDP/串口），实现了协议逻辑与传输机制的解耦。

### 4.2 消息编解码

所有消息编解码使用 `SpanReader` / `SpanWriter`（零分配，ref struct），避免堆内存分配：

```
发送路径：
  应用调用 ReadRegister()
    → 构造 ModbusMessage（填充 Host/Code/Payload）
    → ModbusMessage.ToPacket()
      → SpanWriter.Write(Host) + Write(Code) + Write(Payload)
      → RTU：追加 CRC = ModbusHelper.Crc(data)
      → ASCII：ASCII编码 + LRC = ModbusHelper.Lrc(data) + ":"/CR/LF
      → TCP：前置 MBAP（TransactionId/ProtocolId/Length/UnitId）
    → 发送字节流

接收路径：
  收到字节流
    → ModbusMessage.Read(ref SpanReader)
      → RTU：验证 CRC
      → ASCII：验证 LRC + 解码 ASCII 十六进制
      → TCP：解析 MBAP 头，提取有效载荷
    → 检查 Code 高位（0x80 = 异常响应 → 抛出 ModbusException）
    → 返回 Payload
```

### 4.3 TCP 粘包处理

`ModbusSlave`（服务端）和 `ModbusIp`（客户端）通过 `LengthFieldCodec` 处理 TCP 粘包：

- **偏移量 `Offset = 4`**：跳过事务ID(2B) + 协议标识(2B)
- **长度字段大小 `Size = -2`**：读取长度字段(2B)并减去 2（单元标识 + 功能码已含在 Length 中）

```csharp
// ModbusSlave.OnStart()
Add(new LengthFieldCodec { Offset = 4, Size = -2 });
```

### 4.4 CRC-16-MODBUS 算法

多项式 `x^16 + x^15 + x^2 + 1`（反转多项式 `0xA001`），采用查表法提升性能：

```
初始值：0xFFFF
多项式：0xA001（反转表示）
算法：对每个字节，与寄存器低位异或后右移8次，每次右移前若低位为1则与多项式异或
结果：低字节在前，高字节在后发送
```

### 4.5 LRC 算法（ASCII 变体）

```
LRC = (所有字节之和 & 0xFF) 的二补数
    = (~sum + 1) & 0xFF
```

## 5. 驱动层详细设计

### 5.1 连接单例保证

`ModbusDriver.Open()` 使用双重检查锁（DCL）保证同一驱动实例内只创建一个 Modbus 通道，避免串口/TCP 连接争夺：

```csharp
// 实例化一次 Tcp 连接
if (Modbus == null)
{
    lock (this)
    {
        if (Modbus == null)
        {
            var modbus = CreateModbus(device, node, p);
            // ...
            Modbus = modbus;
        }
    }
}
```

**驱动工厂（DriverFactory）** 在上层保证同一物理地址（同一 IP:Port 或同一串口名）只有一个驱动实例，进而保证只有一个连接。

### 5.2 批处理地址分段（BuildSegments）

将离散的点位地址按连续性合并，减少 Modbus 请求次数：

```
输入点位列表（按地址排序）：
  [addr=0, addr=1, addr=2, addr=5, addr=6, addr=10]

BuildSegments 算法（BatchStep=1）：
  段1：[0, 1, 2]   → 连续，合并为 address=0, count=3
  段2：[5, 6]       → 连续，合并为 address=5, count=2
  段3：[10]         → 独立，合并为 address=10, count=1

单次网络请求次数：3（优化前为 6）
```

**BatchStep 参数**：允许地址间隔 ≤ BatchStep 的点位仍合并为一段，以空读换请求次数减少。

### 5.3 读写流程

```
驱动层 Read 流程：
  ModbusDriver.Read(node, points)
    → BuildSegments(points) → 若干 BatchSegment
    → 对每个 Segment：
        Modbus.Read(code, host, address, count)  // 协议层读取
          → 解析响应字节 → UInt16[]/Byte[]
        → 按点位地址从响应数组中提取对应位置的值
        → 处理位域（:n 语法）、数据类型转换
    → 返回 ThingModel 点位值列表

驱动层 Write 流程：
  ModbusDriver.Write(node, point, value)
    → 解析点位地址（ModbusAddress.TryParse）
    → 确定写功能码（WriteCode 或区域默认码）
    → 类型转换（String/Double/Boolean → UInt16/Boolean）
    → Modbus.Write(code, host, address, value)
```

## 6. 从机（Slave）设计

### 6.1 TCP 从机架构

`ModbusSlave` 继承 `NetServer<ModbusSession>`（NewLife.Net 网络服务器），利用 NewLife.Net 的高性能异步 IO 和会话管理：

```
ModbusSlave (NetServer<ModbusSession>)
├─ Port = 502（标准 Modbus 端口）
├─ Registers : List<RegisterUnit>  // 保持寄存器存储（4x区域）
├─ Coils     : List<CoilUnit>      // 线圈存储（0x区域）
└─ OnStart() → 添加 LengthFieldCodec 粘包编解码器

ModbusSession (NetSession<ModbusSlave>)
└─ OnReceive(data)
     → ModbusIpMessage.Read(data)  // 解析请求
     → 优先匹配自定义处理器 → 无匹配则 switch(msg.Code):
          FC01/FC02 → OnReadCoil()
          FC03/FC04 → OnReadRegister()
          FC05      → OnWriteCoil()
          FC06      → OnWriteRegister()
          FC15      → OnWriteCoils()
          FC16      → OnWriteRegisters()
          FC07      → OnReadExceptionStatus()
          FC11      → OnGetComEventCounter()
          FC12      → OnGetComEventLog()
          FC17      → OnReportServerId()
          FC22      → OnMaskWriteRegister()
          FC23      → OnReadWriteRegisters()
          FC43      → OnReadDevId()
          其他      → 返回 EC01 IllegalFunction
     → 构造响应 ModbusIpMessage
     → Send(rs.ToPacket())
```

### 6.2 数据存储模型

```
RegisterUnit（16位寄存器，大端字节序）
├─ Address : UInt16   // 寄存器地址
└─ Value   : UInt16   // 寄存器值

CoilUnit（1位线圈，打包为字节）
├─ Address : UInt16   // 线圈地址
└─ Value   : Boolean  // 线圈状态
```

### 6.3 从机扩展点

`BeforeRead` 和 `AfterWrite` 事件已实现，在请求读取前和写入后触发，应用层可在事件回调中更新寄存器或处理写入数据：

```csharp
// 读取前回调：可在此处刷新数据源（如从硬件 IO 读取最新值）
slave.BeforeRead += (code, addr, count) =>
{
    // 更新 slave.Registers 或 slave.Coils
};

// 写入后回调：可将写入数据同步到实际执行器（如控制 IO 输出）
slave.AfterWrite += (code, addr, values) =>
{
    // 处理 values，写入硬件
};
```

## 7. NewLife.ModbusRTU 子包设计

串口相关实现独立为 `NewLife.ModbusRTU` NuGet 包，原因：

- 串口 API（`System.IO.Ports`）在 Linux 等平台存在兼容性差异
- 避免仅使用 TCP 的用户引入不必要的串口依赖

### 7.1 串口控制器抽象

```
ISerialPort（接口）
└─ DefaultSerialPort（实现）
     ├─ Open() / Close()
     ├─ Read(buffer, offset, count) : Int32
     ├─ Write(buffer, offset, count)
     └─ 属性：PortName, BaudRate, DataBits, Parity, StopBits
```

通过 `ISerialPort` 接口隔离具体串口实现，便于单元测试时注入 Mock 对象。

### 7.2 ModbusRtu 通信实现

```
ModbusRtu : Modbus
├─ PortName  : String   // 串口名
├─ Baudrate  : Int32    // 波特率
├─ ByteTimeout : Int32  // 字节超时，默认 10ms（用于检测帧结束）
└─ SendCommand(ModbusRtuMessage)
     → 清空接收缓冲区（避免残留数据）
     → 序列化为 ModbusRtuMessage（含 CRC）
     → 串口写入
     → 读取响应（超时检测帧边界）
     → CRC 校验
     → 返回 Payload
```

### 7.3 ModbusRtuSimple 简化实现

`ModbusRtuSimple` 是针对资源受限场景（如工业边缘设备）提供的轻量级串口实现，相比 `ModbusRtu` 减少了部分高级特性，降低代码复杂度和运行开销：

```
ModbusRtuSimple : Modbus
├─ 继承自 Modbus 基类
├─ 直接操作 SerialPort（无 ISerialPort 抽象层）
└─ 适用于对串口依赖注入要求不高的简单场景
```

两者均实现标准 Modbus 协议，动基地址与功能码完全兼容；区别仅在串口抽象层上。

## 9. 关键设计决策

| 决策点 | 选择方案 | 备选方案 | 选择理由 |
|--------|---------|---------|---------|
| 连接复用 | 驱动层单例连接（DCL锁）| 每节点独立连接 | 串口/TCP 物理通道唯一性，避免争抢 |
| 消息编解码 | SpanReader/SpanWriter | Stream/BinaryReader | 零分配，hot path 无 GC |
| 从机网络 | NetServer（NewLife.Net） | System.Net.Sockets 原生 | 高性能，内置粘包/会话管理 |
| 批处理策略 | BuildSegments 地址连续合并 | 每点独立请求 | 减少 RTT，提升轮询效率 |
| 地址解析 | 字符串多格式支持（DO/0x/1x等）| 纯数字 | 兼容主流 Modbus 工具的地址表达习惯 |
| 包分离 | Modbus（TCP）+ ModbusRTU（串口）独立包 | 合并单包 | 串口依赖可选，TCP 用户无串口引用 |
| 校验 | CRC/LRC 内联计算（无第三方） | 第三方校验库 | 算法简单，减少外部依赖 |

## 11. 扩展指南

### 11.1 新增传输方式

1. 继承 `Modbus` 抽象类
2. 实现 `SendCommand(ModbusMessage)` 抽象方法（负责具体字节收发）
3. 覆盖 `CreateMessage()` 返回对应消息子类（如 RTU 变体返回 `ModbusRtuMessage`）
4. 新建对应 `Driver` 类，继承 `ModbusDriver`，实现 `CreateModbus()` 工厂方法

```csharp
public class MyCustomModbus : Modbus
{
    protected override ModbusMessage CreateMessage() => new ModbusRtuMessage();

    protected override ModbusMessage? SendCommand(ModbusMessage message)
    {
        // 自定义传输逻辑
        var data = message.ToPacket();
        // ... 发送并接收
        var rs = new ModbusRtuMessage();
        rs.Read(ref reader);
        return rs;
    }
}

public class MyCustomDriver : ModbusDriver
{
    protected override Modbus CreateModbus(IDevice device, ModbusNode node, ModbusParameter p)
        => new MyCustomModbus { /* 配置 */ };
}
```

## 12. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|--------|
| RTU 串口从机（SLAVE-5/SLAVE-6）已实现 | 可在 RS485 流中作为响应方 | 已新建 `ModbusRtuSlave` 和 `ModbusAsciiSlave`，支持单元测试（`ProcessRequest`） |
| Modbus 协议无认证加密 | 在公网环境下面临未授权操作风险 | 安全部署依赖网络隔离或 VPN，协议层不负责 TLS |
| 无自动重连 | 网络中断后连接丢失，影响通信连续性 | 内置自动重连机制（MaxRetry/RetryInterval），设 MaxRetry=0 可关闭 |
| FC 敏感性误匹配 | 旧设备对 FC23/FC43 不支持时返回 EC01 | 建议上层应用配置 ReadCode/WriteCode 显式指定安全 FC |
| 单连接实例除同一串口多驱动实例 | 多个驱动实例共享串口会产生争强 | 驱动工厂（DriverFactory）在上层保证同一物理地址单驱动实例 |
| 串口 API 跨平台差异 | Linux/macOS 下 `System.IO.Ports` 行为可能差异 | 通过 `ISerialPort` 接口隔离，便于测试和流是阶替换串口实现 |

## 13. WinModbus 演示程序

### 13.1 概述

`WinModbus` 是一个 Windows Forms 桌面演示程序，位于项目根目录 `WinModbus/` 下，用于演示 NewLife.Modbus 库的串口通信能力（ModbusRTU Master 模式）。

### 13.2 功能

- **串口连接管理**：选择串口（COM 端口号）、波特率、连接/断开
- **功能码操作**：支持读写保持寄存器（FC03/FC06/FC16）、读写线圈（FC01/FC05/FC15）
- **实时日志**：在 RichTextBox 中输出通信日志，调试 Modbus 通信过程
- **多界面窗口**：主窗口（FrmMain）+ IO 状态窗口（FrmI6O6N）+ 多路切换窗口（FrmSwitch）+ 输入/输出端口配置

### 13.3 代码结构

| 文件 | 说明 |
|------|------|
| `Program.cs` | 入口点，调用 `XTrace.UseWinForm()` 初始化日志 |
| `FrmMain.cs` | 主窗体：串口连接/断开、寄存器读写、线圈操作 |
| `FrmI6O6N.cs` | IO 状态监控窗口 |
| `FrmSwitch.cs` | 多路切换控制窗口 |
| `InputPort.cs` | 输入端口配置 |
| `OutputPort.cs` | 输出端口配置 |

### 13.4 使用场景

- **开发调试**：在没有真实硬件的情况下验证 ModbusRTU 协议通信
- **功能演示**：向集成商展示 NewLife.Modbus 的串口能力
- **手动测试**：工程师手动读写寄存器/线圈以验证设备响应
